The honest version

What a data scientist actually does.

The myth is that it's all model training. In reality, most of the job is data wrangling, statistical reasoning, and translating noisy signals into a decision the business can actually act on.

The modelling is the easy 10%. The value is in framing the right question, cleaning data nobody trusts, designing an experiment that proves the effect is real, and getting a stakeholder to ship it. That's the part I'm good at — and it's why my models make it to production, not just a notebook.

Concepts & the math behind them

The techniques — and the messy-data traps they solve.

Real training data is never clean. A working reference to the techniques I reach for — the four below in depth, then a quick-reference cheatsheet across the rest.

Deep dives — method, picture, and the trap
Linear regression
ŷ = β₀ + β₁x + ε
best-fit line minimizes total squared error

Fits a straight-line relationship between inputs and a continuous target — the coefficients (β) say how much the prediction moves per unit of each feature. The workhorse for forecasting and quantifying "how much does X drive Y."

PROBLEMCorrelated features make coefficients blow up and flip sign, and a few extreme outliers drag the whole line toward them.
FIXRegularize with Ridge/Lasso to shrink unstable coefficients, drop redundant features, and cap or robust-weight outliers.
Confidence intervals
x̄ ± z·σ√n
shaded band = where the true value likely sits (95%)

A range around an estimate that captures uncertainty: a 95% interval means that if you repeated the experiment many times, 95% of such intervals would contain the true value. It's how you tell a real effect from noise before shipping a change.

PROBLEMSmall or skewed samples give intervals too wide to be useful, and the z-formula quietly assumes a normal distribution the data may not follow.
FIXGather more data where possible, and use bootstrapping — resample thousands of times — to build intervals without assuming normality.
Random forest
ŷ = 1B Σ Tb(x)
many weak trees averaged → one strong prediction

An ensemble that trains many decision trees, each on a random slice of rows and features, then averages their predictions. Individual trees are shaky; averaging many de-correlated ones cuts variance and resists overfitting.

PROBLEMA single deep tree memorizes the data, and on rare-event problems (fraud is a tiny % of orders) a model can hit 99% accuracy by always predicting "not fraud".
FIXBagging + random feature subsets fix overfitting; for imbalance, use class weights or SMOTE and judge on precision/recall, not accuracy.
K-means clustering
argmin Σ Σ ‖x − μ‖²
points snap to the nearest centroid, k = 3

Unsupervised grouping: it partitions data into k clusters so each point sits with its nearest centroid, minimizing within-cluster distance. Used to find natural segments — like seller or user cohorts — when there are no labels to learn from.

PROBLEMYou must choose k up front, unscaled features let one big-range column dominate distance, and a bad random start lands in a poor local optimum.
FIXPick k with the elbow / silhouette method, standardize every feature, and use k-means++ initialization for stable centroids.
Quick reference — the rest of the toolkit
// supervised learning
Logistic regressionσ(z) = 1 / (1 + e⁻ᶻ)
Despite the name, a classifier: it passes a linear score through a sigmoid to output a probability between 0 and 1, then thresholds it. The go-to baseline for "will this happen or not" — interpretable coefficients make it easy to explain to stakeholders.
GOTCHAThe default 0.5 threshold is wrong for imbalanced data — tune it on the precision/recall curve, and calibrate if you need true probabilities.
Gradient boostingFₘ = Fₘ₋₁ + η·hₘ
Builds trees sequentially, each one fitting the errors the previous trees left behind. XGBoost / LightGBM dominate tabular ML — usually the strongest model on structured data like fraud features.
GOTCHAOverfits fast — control it with a small learning rate, shallow trees, and early stopping on a validation set.
Support vector machinemax margin · ‖w‖
Finds the decision boundary with the widest margin between classes; the kernel trick bends that boundary to separate non-linear data. Strong on smaller, high-dimensional datasets.
GOTCHAScales poorly to large data and is distance-based, so features must be standardized first.
k-nearest neighboursŷ = vote(k closest)
No training at all — it labels a new point by the majority of its k closest neighbours. Simple, surprisingly strong, and a good sanity-check baseline.
GOTCHABreaks in high dimensions (everything is "far"), needs scaling, and is slow to predict on big data.
// unsupervised & dimensionality
PCAmaximize var(Xw)
Compresses many correlated features into a few principal components — the directions of greatest variance — keeping most of the information. Used to de-noise, visualize, and speed up models.
GOTCHAAssumes linear structure and is variance-driven, so you must standardize first or the largest-scale feature hijacks component 1.
Hierarchical clusteringlinkage → dendrogram
Builds a tree of nested clusters by repeatedly merging the closest groups — no need to pick k up front, and the dendrogram shows structure at every level.
GOTCHAO(n²) memory makes it impractical on large data, and the result swings with the linkage choice (single vs ward).
// statistics & experimentation
Hypothesis testingp = P(data | H₀)
Quantifies how surprising your result would be if nothing were going on. A small p-value (say < 0.05) is evidence against the null — the formal basis for calling an effect real.
GOTCHAp-value is not effect size, and running many tests inflates false positives — correct for multiple comparisons.
A/B testingrandomized control vs variant
The randomized experiment behind every shipped change: split traffic, measure the metric, and attribute the difference causally to the change. My daily tool for validating a model before rollout.
GOTCHAPeeking early, undersized samples, and novelty effects all fake "wins" — fix the sample size and test window up front.
Bias–variance tradeofferr = bias² + var + noise
The core tension in modelling: too simple and you underfit (high bias), too complex and you overfit (high variance). Good models sit at the sweet spot between them.
GOTCHAChasing training accuracy pushes you straight into high variance — always judge on held-out data.
Central limit theoremx̄ → Normal(μ, σ²/n)
Why statistics works: the average of enough independent samples is approximately normal, whatever the underlying distribution. It's what justifies the confidence intervals and tests above.
GOTCHA"Enough" fails for tiny samples or extreme skew / fat tails — then lean on bootstrapping instead.
// model evaluation
Precision / Recall / F1F1 = 2PR / (P + R)
Precision = of flagged cases, how many were right; recall = of real cases, how many you caught; F1 balances the two. The honest metrics when one class is rare — like fraud.
GOTCHAPrecision and recall trade off against each other — pick the balance from the business cost of a miss vs a false alarm.
ROC-AUCTPR vs FPR, area under
Measures how well a model ranks positives above negatives across every threshold; AUC of 1.0 is perfect, 0.5 is a coin flip. Threshold-independent, good for comparing models.
GOTCHALooks great even on severe imbalance — prefer PR-AUC when positives are rare.
Cross-validationk-fold rotate train/test
Splits data into k folds and rotates which one is held out, so every row is tested once. Gives a stable estimate of real-world performance instead of one lucky split.
GOTCHALeakage kills it — fit scalers / encoders inside each fold, and split by time for time-series.
Confusion matrixTP · FP · FN · TN
The 2×2 table every classification metric is built from — it shows exactly what kind of mistakes a model makes, not just how many. The first thing I read after training.
GOTCHARaw counts mislead on imbalance — normalize by row to see per-class error rates.
// training essentials
Gradient descentθ ← θ − η∇J(θ)
The engine that trains almost everything: repeatedly nudge the parameters downhill on the loss surface until it bottoms out. The learning rate η sets the step size.
GOTCHAη too high and it diverges; too low and it crawls — and unscaled features make the surface lopsided and slow.
Regularization (L1 / L2)J + λ‖θ‖
Adds a penalty on large weights to stop a model memorizing noise. L2 (Ridge) shrinks weights smoothly; L1 (Lasso) drives some to zero, doubling as feature selection.
GOTCHAλ is a dial — too much and you underfit; tune it with cross-validation, not by eye.
Feature scalingz = (x − μ) / σ
Puts every feature on the same footing so one big-range column can't dominate. Mandatory for any distance- or gradient-based method — k-NN, SVM, k-means, PCA, neural nets.
GOTCHAFit the scaler on train only, then apply to test — scaling before the split leaks information.
Train / val / test splitfit · tune · judge once
Three disjoint sets with three jobs: train fits the model, validation tunes hyperparameters, test is touched once at the end for an honest final number.
GOTCHATuning against the test set quietly inflates your score — treat it as sealed until the very end.
